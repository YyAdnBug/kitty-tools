## 1. 启动器搜不到 cmd、应用别名不列出装的应用（bug，已修，没编译）

### 1.1 现在怎么收应用

`Launcher/AppCatalog.cs` 启动先读缓存 `launcher-cache.json`，15 秒后后台扫一遍，开面板时距上次超过 5 分钟再扫。来源：

| 来源 | 收什么 | 过滤 / 去重 |
|---|---|---|
| 开始菜单（所有用户、当前用户的 `Programs`，整棵树） | `.lnk` | 名字带「卸载 / 帮助 / 文档 / manual…」的不收（`Core/StartMenuFilter.cs:10`，在解析目标**之前**、按子串）；目标是网址、文档、卸载程序的不收；按**目标路径**去重 |
| 桌面（当前用户、公用，顶层） | `.lnk`、`.exe` | 同上；`.exe` 过便携软件的名单 |
| 商店应用 | `PackageManager` 的 `AppListEntry` | 名字：显示名 + 包的显示名 |
| App Paths（注册表） | exe | **在 Windows 目录下的不要**（`Core/PortableApps.cs:89`） |
| 运行过的程序（UserAssist，默认开） | exe | 同上，Windows 目录下的不要；过名单 |
| 用户加的文件夹 / 程序 | 往下两层的 exe、单个 `.exe` / `.lnk` | 过名单；同一个文件夹说明一样的留一个 |

PATH 里的 exe、`.url`（Steam 游戏这类）都不收。能搜的名字：标题（资源管理器显示的本地化名）、`.lnk` 文件名、中文的拼音全拼和首字母（`AppCatalog.cs:246–252`）。

### 1.2 为什么搜不到

1. **cmd**（B1）：中文系统上「命令提示符.lnk」是收进来了的（`%AppData%\…\Programs\System Tools\Command Prompt.lnk`），标题「命令提示符」，**副标题写着 cmd**
   （`Core/LauncherText.cs` `AppSubtitle`：中文名后面写 exe 的英文名），但 cmd 不在能搜的名字里——能搜的是「命令提示符」「command prompt」、拼音和首字母 `cp`。
   cmd.exe 本身在 System32，App Paths 和运行过的程序都按「在 Windows 目录下」排掉了。所以打 `cmd` 一条都没有；`regedit`（注册表编辑器）、`taskmgr`（任务管理器）、
   `msconfig`、`services`、`explorer` 一样。英文系统上 `cmd` 也对不上「Command Prompt」（不是开头、不是子串、首字母是 cp）。
2. **名字像文档的应用**（B2）：名单里「文档」「帮助」「help」「manual」按子串一律拦，「腾讯文档」「金山文档」这类本身就是应用的整个丢了。
3. **同一个 exe 的几个快捷方式只留第一个**（B3）：去重只看目标路径。浏览器装的网页应用都指向 `chrome_proxy.exe` / `msedge_proxy.exe`（参数里带 `--app-id`），
   Chrome 几个用户资料的快捷方式都指向 chrome.exe（参数 `--profile-directory`），VS 的开发者命令提示符指向 cmd.exe：只出第一个。
4. **商店应用在中文系统上英文名搜不到**（B4）：「终端」打 `wt` / `terminal`、「计算器」打 `calc`、「画图」打 `paint` 都对不上。

**应用别名不列应用**（B5、B6）：那一栏是一个 `AutoSuggestBox`（`Settings/SettingsWindow.LauncherApps.cs:104–132`）——不打字什么都不出；右边的 + 是查询按钮，
`QuerySubmitted` 没接，点了没反应；键盘 ↓ 选候选时 `SuggestionChosen` 就触发，会直接加上第一个。mac 那一页（`Settings/AppAliasesPage.swift`，外部 PR #13）
一进来就列出全部应用、每行一个别名框，一个应用能起几个别名（逗号隔开），别名也当名字搜（开头、拼音都行）。Windows 当时（PLAN-v18 L5 / D10）换了存法，界面也做成了别的样子。

### 1.3 同类怎么做

读源码（2026-11-26，`main` / `dev` 分支），没在真机上逐个试：

| | PowerToys Run 的程序插件 | Flow Launcher 的程序插件 | 我们（改完） |
|---|---|---|---|

| **快捷方式目标 exe 名能不能搜** | **能**：`LnkResolvedExecutableName = Path.GetFileName(target)`，和名字、本地化名、说明一起模糊匹配取最高分（`Win32Program.cs` `Score`） | **能**（兜底）：名字匹配不够准时再拿 `ExecutableName` 匹配一次（`Win32.cs` `Result`） | 能（B1），和名字同等对待 |

| `.url` | 只收 Steam、Epic | 开了协议才收，Steam、Epic 默认开 | 不收 |

| 目标取法 | `GetPath(SLGP_SHORTPATH)`，目标不存在的快捷方式不收 | 同左，要求 `File.Exists` | `SLGP_RAWPATH` 原样 + `ExpandEnvironmentVariables` |
| 商店应用的执行别名（wt.exe） | 只拿来取图标 | 没处理 | 包名（B4） |

「命令提示符.lnk」在 `%AppData%\Microsoft\Windows\Start Menu\Programs\System Tools\`（微软的任务栏固定文档里的示例路径，Win10 / Win11 都是），
资源管理器里这个文件夹显示成「Windows 系统」/「Windows 工具」这类本地化名；控制面板、运行和它在一起。任务管理器、PowerShell 在所有用户 / 当前用户的
`System Tools`、`Windows PowerShell` 里（第三方资料）。这些文件夹都在我们的扫描范围里——**收是收到了，只是 cmd 这个词对不上**。

## 2. 支持 Windows 10

### 2.1 现在

- **只支持 Windows 11 22H2（10.0.22621）起**：PLAN.md §2 定的；`KittyTools/KittyTools.csproj` 的 `TargetPlatformMinVersion` 是 `10.0.22621.0`。
  但不打包的程序这个值**不拦启动**，安装包（`installer/KittyTools.iss`）也没写 `MinVersion`：Win10 用户现在装得上、开得了多少、在哪坏，**没人试过**。
- **Windows App SDK**（现在用 2.x）官方说法是「向下兼容到 Windows 10 1809」，但只在还受支持的 Windows 上提供支持。WinUI 3 本身能跑 Win10。
- **.NET 10** 的支持表里 Win10 只剩 1607 / 1809 / 21H2 的企业版和 IoT 长期服务版，普通的 22H2 已经不在表里（Win10 停止支持之后删的）；Native AOT 不查系统版本，照样能跑，只是不在官方支持范围里。
- **Win10 的现状**：2025-10-14 停止支持；个人 ESU（同步电脑设置免费、或 1000 积分、或 30 美元）**已经延长到 2027-10-12**，要求 22H2；企业 ESU 最多到 2028 年。
  StatCounter 2026 年 10 月桌面份额：**全球 Win10 25.1 %、Win11 74.3 %；中国 Win10 39.3 %、Win11 56.1 %**。我们的用户中文为主，十个里将近四个还在 Win10。

### 2.2 代码里只有 Win11 才有的东西（`405ed2e4`）

| 用到的 | 最低版本 | 在哪 | Win10 上会怎样 | 要改吗 |
|---|---|---|---|---|
| 云母（Mica）背景 | 22000 | 设置窗（`Settings/SettingsWindow.cs:303`，已经先查 `MicaController.IsSupported`）、全部便签窗口（`Notes/NotesWindow.cs:63`） | `MicaBackdrop` 在不支持的系统上自己换成纯色 | 不用，看一眼 |
| 亚克力（`DesktopAcrylicBackdrop` / `Controller`） | Win10 1809（WinAppSDK 1.2 起） | 轻提示、面板、HUD（`Shell/AcrylicBackdrop.cs`） | 照常 | 不用 |
| DWM 圆角 / 边框色（`DWMWA_WINDOW_CORNER_PREFERENCE`、`DWMWA_BORDER_COLOR`） | 22000 | 轻提示、HUD、截图闪白、钉图、便签那一列、状态屏、无边框窗（7 + 2 处） | 调用返回错误、不抛；窗口是**直角**（Win10 自己就是直角） | 不用；截图时窗口阴影已经按 22000 分了（`Screenshot/WindowShadowShot.cs:151`） |

### 2.3 要做的事和工作量

1. **摸底（半天）**：Windows 测试机上开一个 Hyper-V 虚拟机装 Win10 22H2，先装现在的 0.3.1 看哪里坏（起不起得来、各功能开一遍、`--ui-snapshots`）。后面的工作量以它为准。
2. **最低版本**：`TargetPlatformMinVersion` 改 `10.0.19041.0`（`TargetFramework` 留 22621，新 API 照样能调，调之前按版本分支）；安装包加 `MinVersion=10.0.19041`
   （更低的系统在安装时说「需要 Windows 10 2004 或更新」），zip 版启动时同样查一次；PLAN.md §2、README、官网下载页、发布说明的「系统要求」改成「Windows 10 2004 起（推荐 Windows 11）」。
3. **图标**：108 个码点（104 个在 `Shell/Glyphs.cs`，另有 11 个文件里零散写的），在 Win10 上逐个看，MDL2 里没有的换成两套都有的近似字形（意思和 mac 图标表一致）；写一个自检把全部字形排成一张图，Win10 / Win11 各截一张对着看。
4. **各功能在 Win10 上走一遍**（HANDTEST 2050 起）：剪贴板、启动器（含开始菜单的应用、文件搜索）、翻译（划词的 UI 自动化）、截图（框选、钉图、长截图、识字、识别元素）、
   录屏录音（黄框、系统声音、麦克风）、便签、提醒、状态屏（拦键盘鼠标）、设置导出导入、同步、App 内更新、安装 / 卸载。坏的修，修不了的在 Win10 上藏起来并写清楚。
5. **以后每版**：发版前在 Win10 虚拟机里走一张 10 条的冒烟清单（约 30 分钟）。

规模：**中**，摸底 + 两批（改版本和图标一批、逐个功能修一批），之后每版多 30 分钟。真正的未知数在第 1 步：要是 Windows App SDK 2.x 在 Win10 上有我们没想到的坑（比如自包含的运行时起不来），工作量会变大。

### 2.4 风险

- **没有 Win10 真机**：虚拟机里没有真显卡（录屏、Win2D、亚克力的效果和真机不一样）、没有第二块屏和高分屏，这几样只能等用户反馈。
- **系统本身已经不维护**：Win10 用户碰到的系统 bug 不会再修；.NET 10 也不再把普通 Win10 22H2 列为支持的系统。我们说「尽力支持」，不承诺每个效果都和 Win11 一样。
- **以后每个新功能都多一个要想的系统**：新用到的 Win11 API 要先查版本、写退路。到个人 ESU 结束（2027-10-12）再评估要不要继续。
- **截图 / 录屏的黄框**：Win10 上没法去掉（系统 20348 才给开关），用户会以为「被监控了」，设置 › 录制写一句说明。

## 3. 灵动岛样式的提示

### 3.1 现在

- **Windows 版所有自己的提示都走一个地方**：`Shell/Notice.cs` 的 `NoticeHost`（调用约 295 处）。样子像 Win11 调音量时的浮层：一扇和卡片一样大的小窗口，系统亚克力、
  DWM 画的 8 圆角和阴影，**鼠标所在屏的工作区底部居中、离任务栏 12**；能挂按钮（撤销、在资源管理器中显示、重试）、能显示进度、悬停往上长成卡片、
  到点的提醒「挂着」等处理。不抢焦点、不进截图。**一条系统通知（toast）都没用。**
- **为什么在底部**：0.1.0 时用户定的「不学 mac 的刘海岛，用 Windows 自己的样子」（`MAC-DIFF.md`「mac 的刘海岛在 Windows 上是屏幕底部、任务栏上方的轻提示胶囊」）；
  那之前试过「大透明窗口里画一颗胶囊」，**透明那一层在用户机器上是白的**（`Notice.cs` 文件头、`HudFrame.cs`）。
- **mac 的刘海岛装了什么**（`Shell/Island*.swift`）：所有轻提示（结果、错误、进度、撤销按钮）、到点的提醒挂着；刘海屏上录制计时、长任务挂在刘海两侧的「耳朵」；
  点刘海 / 快捷键叫出「那一张」（快捷动作、最近的提示）；0.9.0 起还有正在播放、电源 / 耳机 / 断网提示、专注模式（这些 PLAN-v20 §4 定了不跟：系统自己有）。
  没有刘海的屏上就是菜单栏下面的黑胶囊。

### 3.2 同类和系统

许可证是读各仓库 LICENSE 文件 / GitHub API 的（2026-11-26）：

| 项目 | 许可证 | 做什么 | 报过的问题 |
|---|---|---|---|
| DynamicWin | CC-BY-SA-4.0，仓库只放发布包 | 常驻顶部：媒体、日历、文件托盘、蓝牙电量 | 盖在全屏游戏上、全屏浏览器里挡住地址栏；CPU 14–50 %；200 % 缩放发糊；多屏总在笔记本屏上 |
| TopNotify | GPL-3.0 | 把**系统通知**挪到顶部：`UserNotificationListener` 听 + 按窗口名找到系统 toast 的窗口、每 10 ms 挪一次 | 换韩语系统就找不到窗口；两块屏缩放不同被截断；疑似分层窗口蓝屏 |
| FluentFlyout | GPL-3.0 | 媒体浮窗、任务栏小组件 | 游戏里掉帧；切歌弹窗把全屏游戏最小化 |

| ModernFlyouts | MIT（2025-11 已归档） | 替换系统音量 / 媒体浮窗 | — |

我们不用它们的代码（规矩：不加第三方依赖；GPL / CC-BY-SA 也不能抄），只看做法和踩过的坑。

系统这边：

- **系统通知改不了样子**：别的程序的通知要搬进来，只能 `UserNotificationListener`（要包身份、用户在弹框里同意；我们是不打包的程序）再去挪系统的窗口（TopNotify 那种，换语言就坏）。
  所以这一条只能是「**我们自己的提示**换成灵动岛样子」，不碰系统通知。
- **顶部正中不是空的**：Win11 拖窗口到顶上会出贴靠布局条；设置 › 系统 › 通知「屏幕弹出窗口的位置」能把音量 / 亮度提示放到顶部居中（2025 年 Insider 起）；
  Game Bar 也在顶部居中；最大化窗口的标题栏、浏览器的标签页也在这一条上。
- **任务栏放顶部 2026-09-29 随 26H2 正式回来了**（不支持自动隐藏、不能每块屏各设）：胶囊要按所在屏的**工作区**顶部算，任务栏在上时让到它下面——现在底部那种也是按工作区算的，同一套。
- **全屏**：`SHQueryUserNotificationState` 能认 D3D 独占全屏、演示模式（`HotKeyBlocker` 已经在用）；进出全屏没有通知，要用时查。微软的通知规范说「用户操作直接带来的结果在 App 自己的界面里说，通知只用于异步的事」，
  没查到反对置顶浮层的官方说法。

### 3.3 评估

- **能做，而且便宜**：不用另起一套——`NoticeHost` 已经是「一扇不抢焦点的小窗口 + 按钮 + 进度 + 悬停展开 + 挂着」，灵动岛样式 = **换位置**（工作区顶部居中、往下长）+ **换皮**（黑底白字，同 mac 的岛）。
  `Core/MonitorLayout.Notice` 加一个顶部的算法配单测，`Notice.cs` 的摆位置和展开方向按设置走；不多开窗口、不常驻、不轮询：**没有额外的 CPU 和内存**。
- **难点只有一个：圆不圆**。DWM 只给 8 / 4 的圆角，46 高的窗口 8 圆角是「圆角卡片」不是「胶囊」。要真胶囊（圆角 = 高的一半）得让窗口外面那一圈透明——0.1.0 正是在这里白了。
  WinUI 3 窗口要透明，得给它一个自己写的透明背景（`SystemBackdrop` 子类往 `ICompositionSupportsSystemBackdrop` 塞一个全透明的画刷），当时是不是这么做的已经查不到；
  **先在用户那台机器上试一个小样**，成了用真胶囊，不成退回 8 圆角的黑条。`SetWindowRgn` 切形状边缘有锯齿、没有阴影，不用。
- **为什么不把默认改成顶部**：一般 Windows 用户习惯系统的提示从右下角 / 任务栏附近出来；顶部正中是标题栏、浏览器标签页、贴靠布局条的位置，提示挡住的是最常点的地方。
  底部挡的是任务栏上方一小块。所以照「按一般用户的默认设置定」：**默认还是底部，灵动岛做成选项**。
- **不常驻**：只在有提示时出现、收起就没了（mac 没刘海的屏上也是这样）。常驻的那种（DynamicWin）挨的骂都在这：挡全屏、挡地址栏、吃 CPU。
- **全屏**：提示本来一两秒就收，热键在全屏游戏里本来就停（PLAN-v17 W2），第一版不另做避让；mac 的「全屏时藏起」也是默认关。
- **多屏、DPI**：同现在，出在鼠标所在的屏、按那块屏的缩放摆。
