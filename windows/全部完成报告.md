# Kitty Tools Windows 版：全部完成报告

2026-10-25。按 `windows/AGENTS.md` 的顺序做到这里。**结论先说**：第一、二、三版做完了；
**第四版做了基础录屏（0.4.0）**：整屏、Alt+R 开始 / 停止、MJPEG AVI，**没有声音、没有选区 / 倒数 / 录制条 /
点按圈 / 按键提示 / 转 GIF / 压缩**；第五版（同步）做完，最终版本 **0.5.0**。没有发布、没有打 tag；
产物只在 `windows/build/release/`。

## 1. 每一版做了什么

### 第一版 0.1.0（2026-10-24）

剪贴板历史（文本 / 图片 / 文件、收藏、搜索、去重、保留期、图片额度、隐私格式、排除的应用）、
翻译（八个服务、流式、划词 / 输入 / 复制即译、自动复制、固定浮窗）、启动器（应用 / 设置页 / 系统命令 /
计算 / 网址路径直达 / 网页搜索 / 使用记录）、截图（冻结帧框选、吸附、放大镜、标注、识字、钉图、截图翻译）、
App 内自动更新、托盘和快捷键。

### 第二版 0.2.0（第 3–6 批）

- 外观按 `PLAN-v2` §3：设置窗换成 Windows 11 设置的样子（导航 + 卡片 + 键帽 + 关于页更新日志）、
  Fluent 托盘菜单、会「长出来」的轻警示胶囊、三块面板的高度 / 高亮 / 键帽 / 预览重做、
  截图工具栏换成真按钮 + 选区里直接打字 + 标注可选中拖动、截图飞入卡片、钉图边框阴影。
- 系统优化（§4）：预读应用目录 + 15 s 刷新、启动 3 s 后预建浮层、空闲两分钟回收缓存并压缩大对象堆、
  搜索折叠文本缓存；发布包去 pdb。
- 自动更新更安全（§5）：只认 GitHub https、跳转逐跳检查、测试发布列表只在调试 / `--update-test`、
  流式下载 + 临时文件 + 改名、已知总长校验；更新后走正常退出。

### 第三版 0.3.0（第 1–6 批）

- 数据安全：每日数据库备份（只留收藏 / 片段 / 收藏夹 / 生词本 / 启动器收藏，留 3 份；启动、锁屏、唤醒触发）；
  打不开时的恢复（用备份 / 重新开始 / 退出，出问题的文件挪进 `damaged-…`）；
  设置与数据的导出 / 导入（和 Mac format 2 通用，密钥 PBKDF2 + AES-GCM，可选密码）；
  功能开关（剪贴板 / 翻译 / 启动器 / 截图，热键、托盘、后台一起停）。
- 翻译：历史与生词本（Ctrl+H、搜索、重译、收藏、删除 / 撤销、CSV / Anki TSV 导出）、查词、替换原文、朗读、
  百度 / 有道 / 火山引擎 / 腾讯云四家（签名纯函数 + 单测）。
- 剪贴板：片段与占位符（`{date}` 等 + `{cursor}`）、收藏夹、备注、范围胶囊、固定面板、Ctrl+K；
  多选（合并 / 一起 / 依次粘贴）、拖出、链接预览（拦截本机 / 内网 / 令牌）、后台识字并可搜。
- 启动器：收藏与顺序、文件搜索、浏览器书签、kill 进程、port 端口。
- 截图：截取上次区域（Ctrl+Alt+Z）、长截图（S 键，实时抓帧 + 拼接）。
- 0.3.0 发布产物已备好（未发布）。

### 第四版 0.4.0（录屏的基础版）

- 手写了一个最小的 AVI（RIFF）写入器，视频流是 MJPEG：GDI 抓屏（整屏，鼠标所在那块）→ 系统的 WIC
  （`Windows.Graphics.Imaging`）编 JPEG → 自己写 RIFF / `idx1`。固定帧率，编码来不及时补重复帧，
  保证时长和真实时间一致。
- Alt+R / 托盘先开截图遮罩选区域（拖动 / 单击窗口 / 整屏），Enter 后倒数 3 秒开始（Esc 取消）；
  录制中有一条深色控制条（红点、计时、✕ 放弃要点两下、■ 停止），可以拖，设了
  `WDA_EXCLUDEFROMCAPTURE`，不会被录进画面；
  托盘录制中多一项「■ 停止录屏 0:12」；录制期间 `SetThreadExecutionState` 防闲置睡眠；
  文件先写同卷的隐藏临时文件、停止后改名放进「视频 › Screen Recordings」并在资源管理器里选中；
  闪退 / 断电后下次启动把临时文件挪进保存目录。
- 设置 › 截图里加「录屏」：帧率 15 / 30、保存目录；功能开关加「录屏」。
- **没做的**：声音（WASAPI 回环 / 麦克风）、选区 / 窗口 / 整屏三种选择、倒数、录制条 / HUD、
  点按圈、按键胶囊、转 GIF、压缩、麦克风权限；输出是 AVI 不是 MP4。

### 第五版 0.5.0

和 Mac 互通的同步：格式（自己写的 JSON 写出器、哈希、版本钟、文件校验，40 个 golden 样本全过）、
四类数据（片段与收藏 / 生词本 / 网页搜索 / 翻译服务）、本机编号 + MachineGuid、账本、
同步文件夹（标记 / device.json / 只写自己的子文件夹 / 占位文件不读 / 原子写）、
执行层（20 秒一轮、启动 / 唤醒 / 立即同步、刹车、状态）、设置页。

## 3. 没做成的（原因、试过什么）

### 第四版：只做了基础版

- **做出来的**：整屏（鼠标所在那块）录成 MJPEG AVI；Alt+R / 托盘开始停止；托盘停止项带计时；
  录制中防闲置睡眠；临时文件 + 改名；闪退后找回；帧率 / 目录设置；功能开关。
- **为什么是 AVI 不是 MP4**：先用 Media Foundation 的 `IMFSinkWriter` 写了 H.264 的完整尝试
  （手写 COM 函数指针、GDI 抓屏 + CPU 转 NV12），修掉了 vtable 索引、内联 `MFSetAttributeSize`、
  临时文件扩展名、COM 初始化等问题后，卡在第一帧 `WriteSample` 不返回（文件 0 字节），
  换软件编码 / 小分辨率 / 补 profile 都一样；那次尝试已撤回。后来改成「WIC 编 JPEG + 自己写 RIFF」，
  一次跑通，MediaPlayer 能解码、时长正确。**AVI 比 MP4 大得多**（1440p15 约 3 MB/s），
  这是基础版的代价。
- **没做**：声音（WASAPI 回环 / 麦克风 / AAC）、带声音 / 按键开关的录制条、点按圈、按键胶囊、
  转 GIF、压缩、麦克风权限、锁屏 / 睡眠自动停止。
- **录音也试过**：手写了 WASAPI 回环（IMMDeviceEnumerator / IAudioClient / IAudioCaptureClient，
  含 MTA 线程、事件回调常量修正），能拿到第一包（峰值 0.372，说明确实采到了系统声音），
  但之后事件不再触发、只录到 10 ms；麦克风路径同样。没拿到可用的录音文件，这次实现已撤回，
  报告只记为「没做成」，不留给用户一个假录音。
- **以后建议**：编码层照 `MFCreateDXGISurfaceBuffer` + WGC 的官方样本走（GPU 纹理直接进编码器），
  不要再走「GDI 抓屏 + CPU 转 NV12 + SinkWriter」这条（这次就是卡在这里）；音频单独做 WASAPI。

### 第五版的简化（和 PLAN-v5 的差距）

- **`decodeExact` 没做**：解开 `value` 再编回去比较这一步没有；现在落地只认自己认识的字段，
  Mac 以后加的新字段会被丢掉。**这是同步最需要先补的一条**（属于安全规矩）。
- 合并引擎按 PLAN 的文字重写（`SyncRecords.swift` 不在这个 checkout 里），语义是「modified 大的赢、
  一样时看钟、墓碑盖住不比它新的」，不是逐行移植；17 个移植用例 / 2000 种子随机测试没有。
- `device.json` 的 epoch 只写不校验「文件夹里的比本机大就换编号」；`SyncDevice.Rotate` 留了接口没接。
- 服务第一次合的去重（协议 + 地址 + 模型一样的自建 AI 只留一个、密钥搬迁）没做。
- 两台 Windows + 假 Mac 的集成测试没写；云盘占位文件、刹车确认交互没测。
- 同步轮在 UI 线程上跑（`ponytail:` 注释说明以后挪后台）。

### 第三版的简化 / 没做

- 第 2 批：浏览器历史（History / places.sqlite）没做；`alt+e` 的「翻译并替换」独立热键没加。
- 第 3 批：Ctrl+K 面板没有「打字过滤」；收藏夹删除不可撤销（条目删除可以）。
- 第 5 批：Firefox 书签没做；文件搜索直接用了目录枚举，没做「两种查法样机对比」；
  端口用 `netstat -ano` 的输出解析（方案写的是 `GetExtendedTcpTable/UdpTable`）。
- 第 6 批：长截图只接了向下滚（向上拼的算法有单测、没有入口）；没有「自动滚动」；
  选区边框排除捕获没做（遮罩收起后没有边框了）。
- 审查方 R12 的几项（高度动画录屏、中文输入法原位文字、卡片拖到资源管理器、等待动画 CPU、
  第二次截图内存）仍然没做，理由见 `REVIEW.md`。

## 5. 替用户定的（摘要）

- 恢复 / 重新开始时出问题的文件一律挪进 `damaged-…`，不删；数据库备份和导出自动备份共用 `backups\`。
- 导出六类默认全勾、密码留空就不带密钥；带密钥的文件留空密码按「密码不对」处理。
- 功能关掉时设置页只显示「已关闭」卡（不做整套灰色控件）。
- 翻译历史只记第一个服务的完成结果；查词只对智谱和 AI 生效；单词模式不自动复制、不给替换。
- 替换原文用结果卡上的按钮；朗读用系统语音；四家密钥字段名照 mac。
- 片段粘贴 / 复制都会展开占位符；`{clipboard}` 取最近的文本历史；收藏夹删除只解除归属。
- 固定面板用 400 ms 轮询前台窗口；Ctrl+K 复用右键菜单；长截图只向下、用 Enter/Esc 全局热键结束。
- 文件搜索范围 / 1.2 s 预算 / 6000 候选；端口按端口号排；书签合并去重、不分 profile；
  收藏的 Kind 存枚举名；`kill` 只结束单个进程。
- 截取上次区域用新热键 Ctrl+Alt+Z；每次截图 / 另存都记住区域，取消不记。
- 录屏：默认 15 fps（可选 30）、整屏（鼠标所在那块）、输出 AVI（MJPEG），保存到「视频 › Screen Recordings」；
  录制中防闲置睡眠；闪退后启动时把临时文件挪进保存目录。
- 同步只写 `devices/<本机>/`；引擎 / 服务整份替换、按 ~order 排；同一条「modified 大的赢」；
  关闭某一类不清账本；轮询 20 秒、同步轮在 UI 线程跑。

## 7. 已知风险（按严重程度）

1. 同步的 `decodeExact` 没做：Mac 新字段会被丢；多设备长期用之前先补。
2. 同步合并语义不是逐行移植，复杂冲突（同秒修改、退库、多台同时删）没有随机测试。
3. 长截图没在真机长页面上验证，吸顶栏 / 页脚的判断只有合成样本的单测。
4. 录屏是 MJPEG AVI（文件大），没在长录制 / 别的播放器上验证；声音和完整录制界面没做。
5. 四家云厂商只做了纯函数级签名验证，没有真实账号请求。
6. 一些文件里有历史遗留的乱码注释 / 个别测试种子字符串（非用户界面），是之前会话的编码事故，
   这次没动它们；用户界面文案是正常的。
7. 高对比度 / 150% 完全没测。
