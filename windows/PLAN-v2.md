## 2. 第一版审查结果（= 第 1 批要修的）

行号都按 `e331781c`，路径相对 `windows/KittyTools/`。

### P0：发布前必须修

1. **检查更新会让全部热键失效**：`App/UpdateService.cs:121`。
   - 每日检查跑在 `System.Threading.Timer`（`:40`）的线程池线程上；发现新版本时直接调 `SettingsService.Save()`，而 `Save` 会在**当前线程**同步触发 `Changed`。
   - 于是 `ShellRuntime.OnSettingsChanged` 在线程池里跑：`HotKeys.RegisterAll` 先清空 id 表、再从错误的线程 `RegisterHotKey` 失败（热键属于隐藏窗口的线程），从此按热键都找不到动作；接着 `Theme.ApplyAccent` 跨线程访问 XAML 资源抛异常，「有新版本」的提示也弹不出来。
   - 结果：**第一次发 Windows 新版本时，所有正在运行的旧版热键全部失效，直到重启。** 第 6 批只测了「手动检查」（在 UI 线程上）和「没有新版本」两条路，所以没碰到。
   - 修法：
     - 检查的后半段（改设置、保存、通知、改托盘）一律 `TryEnqueue` 回 UI 线程；
     - `SettingsService.Save()` 和 `Changed` 只许在 UI 线程上调，Debug 下加断言；
     - `OnSettingsChanged` 只在热键相关的设置真变了时才 `RegisterAll`，不要每次保存都重注册全部热键。
   - 验证：做一个指向本地假发布列表的开关，让每日检查走线程池那条路发现新版本；之后七个热键都还能用，提示也出来了。

### P1

2. **修饰键没处理，取词和粘贴会变成别的组合键**：
   - `Translate/SelectionReader.cs:186` 发 Ctrl+C 之前根本没等修饰键松开。UIA 读不到时几毫秒就走到这里，用户的 Alt（Alt+E）多半还按着，实际发出去的是 Ctrl+Alt+C。
   - `Shell/Paster.cs:106` 的 `WaitModifiersReleased`，注释写「还按着就补发抬起」，实际只在 Alt 按着时敲一下 vkE8，从来不补发 Ctrl / Alt / Shift / Win 的抬起。比如 Shift+Enter（粘贴为纯文本）时 Shift 还没松，发出去的就是 Ctrl+Shift+V。
   - 修法：照 PLAN §5.5 补齐，取词和粘贴共用一个函数：
     - 先等修饰键松开，最多 300 ms；
     - 还按着的，就在 Ctrl+V / Ctrl+C 这组输入的前面补发它们的抬起；
     - 补发 Alt 抬起之前先敲一下 vkE8，免得目标窗口激活菜单栏。
   - 修饰键状态在函数开头读一次，作为参数传进纯函数「要补哪些抬起」，配单测。
3. **还前台失败照样发 Ctrl+V**：`Shell/Paster.cs:33` 只记了一条日志就继续，结果会粘进当时在前台的别的窗口。改成：没回到目标窗口就只复制，轻提示「已复制，没能切回原窗口」。
4. **划词没有「忙时忽略」**：`Translate/TranslateHost.cs:51` 的 `ShowSelection` 是 `async void`，没有进行中的标记。连按两次 Alt+E，两次「备份剪贴板 → Ctrl+C → 还原」会交错，第二次备份到的是第一次 Ctrl+C 的结果，**用户原来的剪贴板就丢了**。加进行中标记（同 mac：忙时忽略重复热键），截图和划词也互相挡住。
5. **多屏、缩放比例不同时尺寸全错**：
   - 出问题的地方：`Shell/OverlayWindow.cs:195`、`Shell/Notice.cs:144`、`Translate/TranslateWindow.cs:410`（以及 `:539`、`:564`），都用 `GetDpiForWindow(自己)` 算目标屏上的像素尺寸，拿到的是窗口**当前所在**那块屏的 DPI。窗口要挪去的屏缩放不同时，比如 720 DIP 在 100% 屏上算成 720 px、摆到 150% 屏上，内容就只剩 480 DIP 宽。
   - `Screenshot/SelectionOverlayWindow.cs:99` 在构造时就取了缩放比例（这时窗口还没挪到那块屏上），可 `FrozenScreen` 里明明已经有每块屏自己的 `Scale`。
   - 修法：一律按目标显示器取 DPI（`GetDpiForMonitor`）；遮罩直接用 `FrozenScreen.Scale`。「工作区 + 缩放 → 窗口像素矩形」写成纯函数，配单测。
6. **截图遮罩的内存和 CPU**：
   - `SelectionOverlayWindow.cs:126` 关闭时只 `RemoveFromVisualTree`，冻结帧的 `CanvasBitmap` 不释放，`FrozenScreen.Bgra`（每块屏「宽 × 高 × 4」字节，在大对象堆里）也要等 GC。这就是第 0 批说的「截一次多 32 MB、关掉不还」。
     修法：关闭时 `_bitmap.Dispose()` 并置空、退订 `Draw` 和指针事件、放掉会话里冻结帧的引用；会话结束后做一次带大对象堆压缩的 GC（`GCSettings.LargeObjectHeapCompactionMode = CompactOnce`），按 D8 量回落。
   - `:692` 的 20 ms 定时器在**每块屏**上**无条件** `Invalidate()`，鼠标不动也按 50 帧 / 秒整屏重画。
     修法：鼠标位置、悬停目标、拖动状态都没变就不重画；顺带查清第 5 批说的「PointerMoved 不可靠」是不是只在注入输入下才出现，真鼠标正常的话改回指针事件、去掉定时器。
7. **写图片进剪贴板时卡住 UI、占着全局剪贴板**：`Clipboard/ClipboardWriter.cs:128` 在剪贴板**打开着**的时候，在 UI 线程上同步等 PNG → DIB 转换（`Task.Run(...).GetAwaiter().GetResult()`），大图要几百毫秒，这期间别的程序都碰不了剪贴板。改成先在后台转好，再打开剪贴板一次写完。

### P2

8. **刚删掉的图片再复制一次会消失**：`Clipboard/ClipboardStore.cs:78`。同一张图还在撤销栈里（删了、面板还没收起）时，`Reclaim` 把它从撤销栈拿出来，可 `Bump` 只在列表里找、找不到就直接返回。结果条目从列表和撤销栈里都没了，库里却还在，重启又冒出来。照 `Record` 的做法把拿回来的条目插回列表最前面，配单测。
9. **托盘**：
   - `Shell/Tray.cs:104`：`NOTIFYICON_VERSION_4` 下右键会依次收到 `WM_RBUTTONUP` 和 `WM_CONTEXTMENU`，两个都弹菜单，很可能弹两次或者重入。实测确认后改成只认 `WM_CONTEXTMENU`；左键认 `NIN_SELECT`，键盘认 `NIN_KEYSELECT`。
   - `:32`：`LoadIcon` 拿到的是 32 px 大图标再缩成托盘尺寸，没用上图标里手调过的 16 px 那张。改用 `LoadIconWithScaleDown`，按当前 DPI 取托盘尺寸（PLAN §5.2）。
10. **轻提示点不穿**：`Shell/Notice.cs:91` 只加了 `WS_EX_TRANSPARENT`，没加 `WS_EX_LAYERED`，鼠标照样被挡住，屏幕顶部中间那块 2 秒内点不了。外观改成胶囊时一起处理（§3.3）。
11. **剪贴板预览图整张解码**：`Clipboard/ClipboardPanel.xaml.cs:325` 的 `BitmapImage` 没设 `DecodePixelWidth`，4K 截图要解码出约 33 MB。按预览区宽 × 缩放比例解码。
12. **流式输出没有空闲超时**：`Translate/TranslateHttp.cs:164`。用了 `ResponseHeadersRead`，`HttpClient.Timeout` 只管到响应头为止，之后服务卡住不发数据，卡片会一直停在「生成中」。给每次读行加空闲超时（本机 / 局域网 180 s，其余 30 s，和 PLAN 的超时一致），超时报网络错误。
13. **启动器的应用目录**：
    - `Launcher/ShellIcons.cs:25` 用 `SHGFI_LARGEICON` 取 32 px 图标，150% 下放大成 48 px，发糊。改用 `IShellItemImageFactory` 按「32 DIP × 缩放」取。
    - 开始菜单里的「卸载 xxx」、说明文档、网址快捷方式也被当成应用列出来；同一个程序在「所有用户」和「当前用户」下各有一个快捷方式时会重复。按快捷方式的目标过滤和去重。
    - PLAN 原本要求枚举 `shell:AppsFolder`，这条在第 4 批改掉了，第二版再评估一次：AppsFolder 里没有卸载项，也覆盖「没有开始菜单快捷方式」的程序。
14. **数据库迁移不是逐版本的**：`Storage/Database.cs:212`，`user_version < 2` 时只 `CREATE TABLE IF NOT EXISTS`，以后改表结构就是坏的。第二版第一次改表之前，先改成逐版本迁移（1→2→3…，每步幂等）+ 迁移单测（同 mac 的 `migratesOldDatabase`）。
15. **抢前台的兜底会激活菜单栏**：`Shell/Foreground.cs:40` 的 `TapAlt` 发的是带 `EXTENDEDKEY` 的 Alt（也就是右 Alt），而且单独按放一次 Alt，会让当时在前台的那个窗口进入菜单栏模式。改成发 vkE8，或者用 `AttachThreadInput` 的做法。

### P3（顺手改）

- 剪贴板一次更新开关剪贴板三次（`IsPrivate` / `Source` / `Read`），每次失败都在 UI 线程上睡 30 ms 重试，最多五次。合成一次打开。DIB 读取加上限。
- 有 HTML 就不读 RTF（PLAN §6.1 写的是两样都存）。
- 文件条目只要有一个文件不在就不让粘（PLAN 和 mac 是全都不在才拦）。
- 剪贴板面板每按一个键就整表重建 `ItemsSource`；`Purge` 用 `List.Contains` 是 O(n·m)。
- `Theme.ApplyAccent` 的 Light / Dark 档是每个通道加减同一个常数，粉色的 Light3 接近白色；改成在 HSL 里调亮度。另外「跟随系统强调色」没有监听 `UISettings.ColorValuesChanged`。
- 识字的 `HasEngine` 只看用户语言里有没有任何一个识字引擎。用户语言里有英文引擎、没有中文时不会提示，中文就识别得很差。
- 单测比 mac 少很多（比如翻译：Windows 18 个，mac 54 个）。PLAN §3 那张表里的纯函数，把 mac 的用例补齐移植。

## 2b. 第 1、2 批之后定下来的（2026-10-24，审查方看完两批的报告和自动更新的代码）

**接受的偏差**（照现在的做法，不用改回 PLAN）：

- **启动器和托盘的图标**用 `SHGetFileInfo(SHGFI_ICONLOCATION)` + `SHDefExtractIcon` 按「32 DIP × 缩放」取，不用 `IShellItemImageFactory`：CsWin32 在 `allowMarshaling=false` 下生成的那个接口要运行时 COM 封送，和红线冲突。以后再遇到 CsWin32 生成不了、或者要封送的 COM 接口，就自己按 vtable 用函数指针调，或者换一个不用 COM 的 Win32 函数。
- **应用目录继续扫开始菜单**（加上第 1 批的过滤和去重），不换 `shell:AppsFolder`。
- **内存**：第一版说的「95–110 MB」是工作集；D8 一律按**专用工作集**算。现在空闲 31.5 MB，四个功能各用一次后约 66 MB，达标。截图的「回到截图前 +5 MB 以内」按**第二次截图起**算：第一次的 +20 MB 是 Win2D / XAML 第一次建全屏画布，只发生一次。
- **截图遮罩**保留 20 ms 轮询鼠标位置，但只在鼠标位置、悬停目标、拖动状态变了时才重画（空闲 CPU 已经是 0）；不用再追查「PointerMoved 不可靠」。
- **发布体积**：多出的 39 MB 是 Native AOT 生成的 `KittyTools.pdb`（60 MB），净发布物两版都是 74 MB 左右。第 6 批按 §4.2 把 pdb 挪出 zip。
- **AOT 下主题资源查不到、NavigationView 崩溃**：根因是发布目录里缺 PRI 文件，第 2 批已经修好并加了构建检查。**第 3 批的设置窗直接用 NavigationView**；所有颜色、画刷照 §3.1 走 `{ThemeResource}`。

**要在第 3 批开头修的**：`REVIEW.md` 的 R1–R3（自动更新只认 GitHub 的 https 地址、更新后走正常的退出流程、下载流式写文件）。

**§4.2 的预建窗口**：浮层窗口和翻译浮窗照做（启动 3 s 后预建，量一下空闲内存，必须仍 ≤ 50 MB）；**截图遮罩不预建**（会让空闲多出 20 MB，超过 D8）。

## 3. UI 风格

原则不变（PLAN §5.8）：**品牌留下，皮肤用 Fluent**；颜色只标「现在该操作的东西」；和精度有关的交互不做动画；系统关了动画效果时只留淡入淡出。

### 3.1 公共底座（第 2、3 批）

- **主题资源**：所有颜色、画刷、圆角、字号都走 `{ThemeResource}` 或 WinUI 的主题资源，把 64 处写死的颜色清掉。截图的深色 HUD 那一套不跟深浅色变，常量集中放在 `Theme.Shot` 一个地方。高对比度主题下每个界面截一张图检查。
- **动效 `Shell/Motion.cs`**：mac 的七条命名曲线（instant / snap / glide / settle / pop / island / retract，参数见 `macos/KittyTools/Shell/Style.swift` 的 `Motion`），用 Composition 的弹簧动画实现（`DampingRatio = 1 − bounce`、`Period = duration`）。提供四个现成的用法，各界面只调这几个：
  - 入场：透明度 0→1 + 下落 6 px；
  - 高度变化：顶边不动；
  - 选中高亮滑动；
  - 小东西出现：从 0.85 放大到 1。

  读 `UISettings.AnimationsEnabled`，关掉时只留淡入淡出。
- **无障碍**：只有图标的按钮都设 `AutomationProperties.Name`；列表项有可读的名字（标题 + 类型 + 时间）；截图工具栏能用读屏软件操作；全键盘可用。

## 4. 系统优化

### 4.1 先量清楚（第 2 批）

- 做一个内存探针：Debug / Release 都能用命令行开关逐项量。照 mac 的 `MemoryProbeTests` 的思路，每一项量专用工作集，空闲 30 s 后读：
  - 只有托盘；
  - 剪贴板（含 5000 条）、启动器、翻译浮窗、截图遮罩、钉图、设置窗，各自打开再收起之后；
  - 收起两分钟后。

  报告里给出 95–110 MB 是由哪几样构成的（XAML 框架、`XamlControlsResources`、应用目录和图标、剪贴板条目、GC 堆没还的部分……）。
- **不许用 `EmptyWorkingSet` / `SetProcessWorkingSetSize` 压数字**：它们只是把页换出去，数字好看了，实际下次用的时候会大量缺页、更慢。
- 发布体积：对比第 1 批和第 6 批的发布目录，找出多出的 39 MB 在哪。先看是不是 Native AOT 生成的 `KittyTools.pdb`（`Directory.Build.props` 里是 `DebugType=embedded`，AOT 还会另外出一个原生 pdb）。

### 4.2 优化项（第 6 批按量出来的数逐项做，目标见 D8）

- **截图**：§2 第 6 条；遮罩不空转。
- **空闲回收**（同 mac 的做法）：所有面板都收起两分钟后，放掉可以重建的东西：剪贴板预览图、启动器里暂时不用的图标位图、识字引擎、Win2D 设备上的缓存、大对象堆里的临时缓冲。浮层窗口本身留着（第 0 批量过，销毁只省 0.3 MB）。
- **启动**：
  - 应用目录不在启动时马上扫：先读上次存在磁盘上的结果（名字、目标、图标 PNG），启动 15 s 后在后台低优先级刷新一次；
  - 启动 3 s 后预建浮层窗口和翻译浮窗（约 +10 MB，换来第一次按热键也只要 15 ms，而不是 115–256 ms）。
- **AOT 设置**：
  - 逐项实测后再决定要不要开：`IlcOptimizationPreference=Size`、`ConcurrentGarbageCollection=false`（少一个后台 GC 线程）、`UseSystemResourceKeys=true`；
  - **不开** `InvariantGlobalization`：中文按当前区域排序要用到。
  - 每项的「体积 / 内存 / 启动时间」变化写进报告。
- **发布物**：zip 里不放 pdb，单独存一份（同 mac 留 dSYM 的做法），以后用来解析崩溃转储。
- **CPU**：
  - 等待动效用 Composition（§3.7）；遮罩不空转；
  - 量一下空闲时（只有托盘、什么都不做）进程的 CPU，应该长期为 0；
  - 隐藏的窗口上不能挂着定时器。

## 5. App 内自动更新（D6，第 2 批）

- 检查照旧（PLAN §10，只认 `windows-v*`）。有新版本时，托盘和设置 › 关于里给「更新到 x.y.z」。点了之后：
  1. 下载对应架构的 zip 到 `%LOCALAPPDATA%\KittyTools\updates\`；
  2. 用 release 里附的 `.sha256` 文件校验（发布脚本要同时生成这个文件）；
  3. 解压到临时目录，检查里面有 `KittyTools.exe`、版本号对得上；
  4. 把正在运行的 exe 和要替换的 DLL 改名成 `*.old`（Windows 允许改名正在运行的文件），再把新文件拷进去；
  5. 用新 exe 带 `--updated` 参数重新启动，自己退出；新进程启动后删掉 `*.old`，轻提示「已更新到 x.y.z」。
- **任何一步失败都要能回到原样**：改名失败就不动；拷了一半失败就把 `*.old` 改回去；最后都要能启动旧版本。
- 安装目录没有写权限时（比如装在 Program Files）不自动更新，打开发布页，并说明原因。
- 验证：本地假发布列表 + 两个版本号不同的 zip，覆盖成功、校验失败、改名失败三条路。
