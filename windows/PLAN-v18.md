用户转来的反馈：「有些便携软件在启动器里搜不到」。**原因**：`Launcher/AppCatalog.cs` 的 App 只从两处来——开始菜单
（所有用户 + 当前用户 `Programs` 下的 `.lnk`）和商店应用（`PackageManager`）。便携软件没装、不进开始菜单，桌面上的快捷方式、
注册表 `App Paths`、用户双击运行过的 exe 都没扫；文件搜索（`open` / `find`）只查桌面 / 文档 / 下载等七个目录，也不进普通搜索。
**对标**：PowerToys Run 的「程序」插件扫开始菜单、桌面、注册表、PATH，扫不到的让用户在程序所在目录建快捷方式；
Flow Launcher 的「程序」插件另有「程序来源」（用户加目录、按后缀收），能关掉卸载程序和重复的；Listary / Everything
是全盘文件名索引（NTFS 的 MFT），exe 按文件名搜到。我们不做全盘索引（要管理员权限读 MFT，或者自己常驻一份索引），
走「系统已经记着的 + 用户点名的」。这一批照推荐做，§4 末尾的 P1–P4 用户不同意再改。

**跟 mac 的关系**：Windows 独有（mac 的 App 都在应用程序目录里），mac 不跟。

| # | 事 | Windows |
|---|---|---|
| A1 | **桌面上的快捷方式和 exe 也算 App**：当前用户桌面和公用桌面（`SpecialFolder.DesktopDirectory`、`CommonDesktopDirectory`）顶层的 `.lnk`、`.exe`（不进子文件夹）。过滤、去重照开始菜单那套（`StartMenuFilter.ShouldSkip` / `ShouldSkipTarget`，按解析出来的目标去重，开始菜单里已有的那条留着）；副标题写「桌面」。 | 并进 `ScanStartMenu` 的循环（只是多两个目录、`SearchOption.TopDirectoryOnly`），不另起一套。 |
| A2 | **注册表 `App Paths`**：`HKCU` 和 `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\App Paths\*.exe` 的默认值（exe 路径，可能带引号、带 `%环境变量%`，用 `LauncherOpeners` 里现成的「命令行 → exe 路径」那段解开）。文件不存在、在 `C:\Windows` 下的不要（`notepad.exe` 这类系统程序开始菜单里已有，`App Paths` 里还有一堆没界面的）。标题：exe 的 `FileVersionInfo.FileDescription`（常是中文名，空的或等于文件名时用文件名去掉 .exe），名字里同时放文件名，好按英文搜。 | 只读注册表，几十项，毫秒级；和 A1 一样按目标去重。 |
| A3 | **用户运行过的 exe**（便携软件主要靠这一条，不用设置）：资源管理器记的 UserAssist（`HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\UserAssist\{CEBFF5CD-ACE2-4F4F-9178-9926F41749EA}\Count`，值名是 ROT13 编码的路径，值是 72 字节：偏移 4 的 `uint` 是运行次数、偏移 60 的 `FILETIME` 是最后运行时刻）。收：解码后是绝对路径、扩展名 `.exe`、文件还在、运行次数 ≥ 1、不在 `C:\Windows` 和本 App 自己的安装目录、过得了 `StartMenuFilter.ShouldSkipTarget` 和下面 A5 的名单、和已有的 App 目标不重复的；值名开头是已知文件夹 GUID（`{6D809377-…}` = Program Files 这类）的用 `SHGetKnownFolderPath` 换成真路径，换不出来的跳过。最后运行时刻进 `LauncherItem` 给同分排序用（同 mac 的 `systemUse`，2026-11-10 `ea0c2813`）。系统设置 › 隐私 ›「允许 Windows 跟踪应用启动」关着时这里是空的，不报错。 | 纯函数放 Core（ROT13 解码 + 72 字节解析 + 过滤，配单测、带几条真机抓的样本），读注册表在 App 侧。实测本机条数和耗时写进 REVIEW。 |
| A4 | **用户自己加的「应用文件夹」和单个程序**：设置 › 启动器加一节「应用文件夹」，列表 +「添加文件夹…」「添加程序…」（文件选择器，`.exe` / `.lnk`）；启动器里文件搜索结果是 `.exe` 时动作菜单加「添加到启动器的应用」。文件夹往下扫**两层**（`D:\Tools\xxx\xxx.exe` 这种最常见），每个文件夹最多收 500 个 exe、超了只记日志；同一个子文件夹里有好几个 exe 时都收（过滤靠 A5）。列表跟着导出导入（只是路径；别人的路径导进来不存在就灰着写「找不到」，不删）。 | 存设置里一段路径列表；扫描跟着 `AppCatalog` 现在的节奏（启动后 15 秒、打开面板时超过 5 分钟才再扫），结果进 `launcher-cache.json`。文件夹在不在线的网络盘上：枚举放后台、每个文件夹 2 秒超时，超时那个这一轮跳过。 |
| A5 | **不把没用的 exe 搜出来**（A3、A4 都过）：文件名（不分大小写）含 `unins`、`uninstall`、`setup`、`install`、`update`、`updater`、`upgrade`、`crash`、`report`、`helper`、`elevate`、`vc_redist`、`dxsetup` 的不收（名单宁短：`7zFM.exe` 这类有用的不能误伤）；`FileVersionInfo.FileDescription` 含「卸载」「安装」「更新」的不收；没有图标（`ExtractIconEx` 拿到 0 个）的命令行小工具不收。同一个文件夹里 FileDescription 一样的只留一个（`xxx.exe` 和 `xxx64.exe` 留 64 位那个）。用户在动作菜单里对一条 App 点「从启动器里隐藏」：记进隐藏名单（按目标路径，跟着导出导入），设置 › 启动器「应用文件夹」底下能看到、能恢复。 | 名单写成 Core 的纯函数配单测（拿真机上 `D:\` 常见便携软件目录的文件名列一份当样本）；`ponytail:` 注释写上「按名字猜，漏的靠用户隐藏」。 |
| A6 | **便携软件要在自己的目录里启动**：现在 `LauncherOpeners.Start` 不设工作目录，会继承 Kitty Tools 的；很多便携软件按当前目录找配置文件，打开就像第一次用。打开 `.exe` 时 `WorkingDirectory` 设成 exe 所在目录（`.lnk` 不管，快捷方式里自己写了「起始位置」）。 | 一行。开始菜单里直接指向 exe 的那些不受影响（它们走的是 `.lnk`）。 |

性能目标：A1–A3 加起来在一台装了 150 个程序的机器上 < 100 ms（后台线程，不碰 UI 线程）；A4 每个文件夹两层、500 个上限，
本地盘 < 200 ms。都写进 REVIEW 的实测。手测接着 `HANDTEST.md` 末尾往下编：桌面上的便携软件、`App Paths` 里的程序、
在资源管理器双击过一次的 `D:\Tools\xxx\xxx.exe`、加了文件夹以后搜得到而 `unins000.exe` / `updater.exe` 搜不到、
隐藏和恢复、关掉「跟踪应用启动」后 A3 为空不报错、便携软件打开后读的是自己目录里的配置。

| # | 问题 | 推荐 |
|---|---|---|
| P1 | A3 读 UserAssist 默认开不开 | **开**，设置 › 启动器「应用文件夹」那一节里一个开关「把运行过的程序也列出来」。只在本机读，不导出、不同步；不开的话便携软件还是要用户自己加文件夹，大多数人不会去找这个设置。 |
| P2 | 要不要扫 PATH | **不扫**。PATH 里一大半是命令行工具（git、python、node），列成 App 全是噪音；要的用户用 A4 加单个程序。 |
| P3 | 要不要像 Everything 那样全盘索引 | **不做**。读 MFT 要管理员权限，自己建索引要常驻、占内存；系统的 Windows 搜索索引默认不收 `D:\` 这类目录。 |
| P4 | A4 往下扫几层 | **两层**。一层漏掉 `Tools\xxx\xxx.exe`，三层起开始把插件、运行库里的 exe 也扫进来。 |
